# 03. Дорожная карта

Шаги идут по порядку. Шаг не начинается, пока не закрыты критерии предыдущего, кроме явно названных блокеров.

## Шаг 0. Документация и структура репозитория

**Цель.** Зафиксировать бриф, архитектуру, модель данных и планы, не ставя пакеты и не трогая конфиги сервера.

**Задачи.**

- README, `docs/00`–`docs/07`, шаблон отчёта и отчёт шага.
- `.gitignore` для Laravel.
- Положить как есть `reference/landing-index.html` и `reference/admin-kit-install.md`.
- Коммит `step-00: docs and repo structure`, push в `origin main`.

**Приёмка.**

- В `main` есть перечисленные файлы, нет `.env` и секретов.
- Модель данных содержит типы и индексы.
- В документации описан перенос Laravel из временного каталога.
- Отчёт шага заполнен по шаблону.

## Шаг 1. Подготовка сервера

**Цель.** Сервер готов принять Laravel, MySQL, nginx и certbot. План и уже сделанное — [04-server.md](04-server.md).

**Задачи.**

- Довести SSH до входа только по ключу и запрета root-логина, если проверка покажет, что это ещё не так.
- Часовой пояс ОС оставить UTC, если он уже UTC.
- Swap, раз RAM меньше 4 ГБ.
- ufw: OpenSSH, 80, 443.
- fail2ban для SSH.
- nginx.
- PHP 8.5-FPM из архива Ubuntu и расширения mbstring, xml, curl, mysql, zip, bcmath, intl, gd, opcache, readline. Сокет `/run/php/php8.5-fpm.sock`.
- MySQL, отдельная база и пользователь приложения.
- Composer.
- Node 22 LTS.
- certbot.
- Проверить unattended-upgrades.
- Ежедневный дамп БД, 14 архивов. Cron `schedule:run` — на шаге 2, когда появится `artisan`.
- supervisor — пакет сейчас, worker только если появится очередь.

**Приёмка.**

- `php -v` — 8.5, нужные модули в `php -m`.
- nginx установлен, default site снят. Ответ на 80 появится с vhost на шаге 2. MySQL принимает пользователя приложения только с localhost.
- ufw включён, SSH по ключу с машины разработчика жив, парольный вход и root по SSH закрыты.
- Swap активен, если RAM меньше 4 ГБ.
- Пакеты и версии записаны в `reports/step-01.md`.

## Шаг 2. Laravel, кит, SSL

**Цель.** Пустое приложение Laravel 13 с китом v0.5.0 открывается по HTTPS.

**Задачи.**

- Создать Laravel 13 во временном каталоге и перенести в `/var/www/nadia` по правилам из [01-architecture.md](01-architecture.md). Не затереть `docs/`, `reference/`, `reports/`, `README.md`, `.git`. Не коммитить `.env`. Скелет Laravel 12 не апгрейдить, а заменить чистым 13.
- Поставить кит по `reference/admin-kit-install.md` версии v0.5.0. В примере nginx там указан сокет `php8.3-fpm.sock`; на этом сервере сокет `/run/php/php8.5-fpm.sock`. Саму инструкцию не переписывать.
- База в `.env` — пользователь и БД из шага 1.
- Выпустить сертификат certbot на `nadia.owlsolutions.net`.
- nginx: `root` на `public`, сокет `/run/php/php8.5-fpm.sock`, редирект HTTP → HTTPS.
- Зафиксировать фактические колонки `ai_provider_settings` в отчёте шага.
- Права: владелец `deploy:www-data`, setgid на корне уже 2775. На `storage` и `bootstrap/cache` — ACL для `www-data`, как в [04-server.md](04-server.md).

**Приёмка.**

- `https://nadia.owlsolutions.net` открывает Laravel без предупреждения сертификата.
- Вход в админку кита работает.
- `owl-admin/health` отвечает успешно.
- В git нет `.env`, `vendor/`, `node_modules/`.

Инструкция кита лежит в `reference/admin-kit-install.md`. Если кит v0.5.0 не встанет на PHP 8.5, вопрос PHP открывается снова.

## Шаг 4. Лендинг и заявки

**Статус.** Выполнен. Проверка — `php artisan test` и `php artisan nadia:smoke`.

**Цель.** Лендинг совпадает с макетом, форма создаёт заявку.

**Сделано.**

- `reference/landing-index.html` перенесён в Blade. CSS и JS — отдельные Vite-entry, без React/Inertia.
- `POST /leads`: CSRF, honeypot, `started_at` < 2 секунд → spam без события, throttle 5/мин, валидация. Успех шлёт `LeadCreated`.
- Пишутся UTM, referrer, landing path, visitor_id, ip_hash, user_agent, `source=form`.
- Раздел «Заявки»: таблица, фильтры, карточка, статус, заметка, CSV. Если `source=chat` — плейсхолдер переписки (шаг 5).
- KPI Leads на дашборде — последние 30 дней без spam. Бейдж новых заявок в меню.

**Приёмка.**

- Визуальное сравнение с `reference/landing-index.html`: те же блоки и стили, отличия формы перечислены в `reports/step-04.md`.
- Валидная форма создаёт строку в `leads`. Honeypot и слишком быстрая отправка сохраняются как spam. Невалидные поля дают 422. Шестой запрос за минуту — 429.
- CSV содержит отфильтрованные строки.
- Админка по-прежнему без пикселей и маячка.

## Шаг 5. ИИ-чат

**Цель.** Посетитель общается с активной моделью кита, контакт из диалога становится заявкой.

**Задачи.**

- Кнопка в правом нижнем углу. Скрыта, если чат выключен или нет активного провайдера.
- `POST /chat/message` по правилам из [01-architecture.md](01-architecture.md): лимиты 1000 символов, 30 сообщений на сессию, 20 сообщений контекста, ~500 output tokens, throttle 20 запросов в минуту с IP.
- Вкладка Assistant сейчас заглушка. Сохранить `assistant_system_prompt`, `assistant_greeting`, `chat_enabled`.
- System prompt и приветствие из настроек Assistant.
- Вырезать `<lead>{json}</lead>`, создать заявку `source=chat`, проставить `lead_id` и `chat_session_id`.
- Раздел «Чаты»: сессии и переписка. Из заявки чата — переход в эту сессию.

**Приёмка.**

- При выключенном чате или без активного провайдера кнопки в HTML нет.
- Ответ идёт от провайдера, выбранного в настройках AI кита.
- Блок `<lead>` не виден посетителю. Заявка создаётся только при имени и email или телефоне.
- 31-е сообщение сессии и текст длиннее 1000 символов отклоняются.
- В админке видна переписка.

## Шаг 6. Аналитика

**Цель.** Визиты лендинга и конверсии считаются своей аналитикой.

**Задачи.**

- Cookie `visitor_id` на 1 год и сессия трекинга на 30 минут неактивности. Имя session-cookie не пересекается с cookie Laravel.
- Маячок `POST /t` через `sendBeacon` только на лендинге. Throttle 60 запросов в минуту с IP.
- `ip_hash` с суточной солью. IP не хранить.
- Запросы ботов не писать. Колонки `is_bot` нет.
- События `form_submit`, `chat_open`, `chat_lead`.
- Раздел аналитики: визиты, уникальные посетители, просмотры, график по дням (сутки `America/Chicago`), топ рефереров, UTM, устройства и браузеры, три конверсии. Периоды 7 / 30 / 90 и произвольный.
- Dashboard использует ту же формулу конверсии.
- Scheduled command удаляет `page_views` и `site_events` старше 12 месяцев.

**Приёмка.**

- Просмотр лендинга пишет `page_views` без сырого IP. Запрос бота строки не создаёт.
- Страницы админки строк в `page_views` не создают.
- Команда очистки снимает строки старше 12 месяцев и не трогает более свежие.
- Смена периода меняет цифры.
- События трёх типов появляются при соответствующих действиях.

## Шаг 7. Пиксели и коды

**Цель.** Сниппеты и ID счётчиков управляются из админки и живут только на лендинге.

**Задачи.**

- CRUD `tracking_codes`.
- Поля Meta Pixel ID и GA4 Measurement ID в настройках.
- Вставка активных сниппетов в `head` / `body_start` / `body_end` лендинга по `sort`.
- После успешной заявки — `fbq('track','Lead')` и gtag `generate_lead`, если соответствующий ID задан.
- Не выводить это в layout админки.
- Страница `/privacy` — простой текст, ссылка на неё в футере лендинга. Баннер согласия не делать.

**Приёмка.**

- Выключенный сниппет не попадает в HTML.
- В HTML админки нет ни сниппетов, ни `fbq`, ни gtag этого сайта.
- При пустых ID событий Lead нет. При заполненных ID успешная заявка их вызывает.
- `/privacy` открывается, футер лендинга на неё ссылается, баннера согласия нет.
